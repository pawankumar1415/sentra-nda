# rag_function — NDA Narrative Validation RAG Pipeline

An open-source, self-contained RAG (Retrieval-Augmented Generation) pipeline for validating NDA project narrative text. Replaces the Azure AI Foundry Agent + Azure AI Search setup with a fully controllable stack built on **Azure PostgreSQL + pgvector** and **Azure OpenAI**.

## Overview

The pipeline performs **two-layer validation** of NDA project narratives:

- **Layer 1 — Guidance & Structure:** Checks the narrative follows the NDA Good Practice guidelines (sentence templates, formatting rules, acronym expansion, date formatting, no building numbers, etc.)
- **Layer 2 — Data-Driven:** Checks whether material EAC movements (≥ £0.1m) and schedule slippages are adequately explained in the narrative.

Data is retrieved from a **PostgreSQL vector store** populated by ingesting NDA MPPR Excel files. The validation response is generated by **Azure OpenAI GPT** using the retrieved project data as context.

### Data Flow — Ingest

```
Excel Upload (.xlsx)
  → Parse '5a)NDA MPPR' sheet (columns A–AK)
  → Drop blank rows, extract all fields per project row
  → Build searchable text chunk (all fields concatenated)
  → Batch embed via text-embedding-3-small (1536 dims)
  → Upsert into nda_projects with ON CONFLICT DO UPDATE
  → Return { status, period, indexed_count }
```

### Data Flow — Validate

```
POST { narrative, project_name, period }
  → Embed narrative text (1536-dim query vector)
  → Cosine similarity search in nda_projects (top-k=5)
  → Load EAC variance from lifecycle_eac_variance.xlsx
  → Classify EAC flag: none / minor / material / major
  → Build augmented prompt: system_prompt + retrieved chunks + EAC data + narrative
  → Call GPT with response_format=json_object
  → Parse and return structured Layer 1 + Layer 2 result
```

When creating the Azure PostgreSQL Flexible Server, navigate to:
**Server → Settings → Server parameters → Search `azure.extensions`** and add `VECTOR` to the allowlist. Then run `setup_db.py` — it will execute `CREATE EXTENSION IF NOT EXISTS vector;`.

- Python 3.11+
- A virtual environment with `rag_function/requirements.txt` installed:

## Database Setup

Run **once** after provisioning your PostgreSQL server:

```powershell
python setup_db.py
```

This will:
1. Connect using credentials from `rag_function/local.settings.json`
2. Create the `vector` extension
3. Create the `nda_projects` table
4. Create the IVFFlat cosine similarity index (`lists=50`)
5. Create a secondary index on `period_short_name`
6. Print a verification summary of all columns and indexes

Expected output:
```
✅ Loaded credentials from rag_function\local.settings.json
✅ Connected to PostgreSQL

  ✅ Enable pgvector extension
  ✅ Create nda_projects table
  ✅ Create IVFFlat cosine index on embedding
  ✅ Create period index for fast filtering

Table 'nda_projects' columns:
    project_id                     text
    project_name                   text
    embedding                      USER-DEFINED
    ...

✅ Schema setup complete — ready for ingest.
```

### nda_projects Schema

| Column | Type | Description |
|---|---|---|
| `project_id` | TEXT PK | `"{period}\|{project_code}"` — unique per period+project |
| `project_name` | TEXT | Project/programme title |
| `period_short_name` | TEXT | Reporting period, e.g. `P07` |
| `rag_status` | TEXT | DCA RAG status (Amber/Red/Green) |

| `capability_capacity_rag` | TEXT | Capability & Capacity RAG |

## API Reference

### POST /api/ingest

Parses an NDA MPPR Excel file, embeds all project rows, and upserts them into the PostgreSQL vector store.

**Request:**

Send the Excel file as either:
- `multipart/form-data` with field name `file`
- Raw binary body (`Content-Type: application/octet-stream`)

**Response (200):**
```json
{
  "status": "ok",
  "period": "P07",
  "indexed": 42
}
```

**Response (400) — wrong sheet name or no data:**
```json
{
  "error": "Sheet '5a)NDA MPPR' not found. Sheets present: [...]"
}
```

**Example (curl):**
```bash
curl -X POST https://<your-function>.azurewebsites.net/api/ingest?code=<key> \
  -F "file=@P07_Exec_Project_Summary.xlsx"
```

---

### POST /api/validate

Validates a project narrative against retrieved project data and EAC variance figures.

**Request body (JSON):**

```json
{
  "narrative":     "The SRO DCA remains Amber because...",
  "project_name":  "Security Systems Architecture",
  "period":        "P07",
  "top_k":         5
}
```

| Field | Required | Default | Description |
|---|---|---|---|
| `narrative` | ✅ | — | The narrative text to validate |
| `project_name` | ✅ | — | Used for EAC lookup and vector search filtering |
| `period` | ❌ | `null` | Reporting period for EAC lookup (e.g. `"P07"`) |
| `top_k` | ❌ | `5` | Number of similar project chunks to retrieve |

**Response (200):**

```json
{
  "layer1": {
    "compliance_score": 8,
    "issues": [
      "Dates not written in full — 'May-24' should be '15th May 2024'",
      "DCA acronym not expanded on first use"
    ],
    "passed": [
      "Narrative is flowing prose, not bullet points",
      "EAC sentence present",
      "RAG status sentence present"
    ]
  },
  "layer2": {
    "eac_explained": true,
    "schedule_explained": true,
    "data_flag": "material",
    "issues": []
  },
  "suggestions": [
    "Replace 'The DCA remains Amber' with 'The Delivery Confidence Assessment (DCA) remains Amber because...'",
    "Replace 'May-24' with '15th May 2024'"
  ],
  "overall_verdict": "PASS_WITH_WARNINGS",
  "_meta": {
    "project_name": "Security Systems Architecture",
    "period": "P07",
    "chunks_used": 5,
    "eac_flag": "material",
    "eac_variance_m": 0.3,
    "schedule_days": 57
  }
}
```

**Verdict values:**

| Verdict | Meaning |
|---|---|
| `PASS` | Narrative fully compliant — no issues |
| `PASS_WITH_WARNINGS` | Minor issues found but narrative is acceptable |
| `FAIL` | Significant structural or data issues — must be revised |

## How It Works

### Embedding Strategy

Each project row from the Excel file is converted into a single **text chunk** by concatenating all meaningful fields:

```
Project: Security Systems Architecture | Code: SSA-001 |
Period: P07 | DCA RAG Status: Amber | EAC (£m): 12.3 |
EAC Variance (£m): 0.3 | Schedule Variance (days): 57 |
Narrative: The SRO DCA remains...
```

This chunk is embedded using `text-embedding-3-small` (1536 dimensions) and stored in PostgreSQL. At query time, the **narrative being validated** is embedded using the same model and the closest project records are retrieved via cosine similarity.

### EAC Variance Classification

| Threshold | Flag | Action |
|---|---|---|
| `abs(variance) < £50k` | `none` | No mention required |
| `£50k ≤ abs(variance) < £0.1m` | `minor` | Should acknowledge briefly |
| `£0.1m ≤ abs(variance) < £0.5m` | `material` | Must be explained in narrative |
| `abs(variance) ≥ £0.5m` | `major` | Requires explicit, detailed explanation |

### IVFFlat Index

The PostgreSQL index uses `ivfflat` with `lists=50`, which works well for up to ~5,000 rows. If the dataset grows significantly:
- `lists=100` → up to ~50,000 rows
- Consider switching to `hnsw` for >50k rows (pgvector 0.5+)

## Local Testing

With `rag_function/local.settings.json` filled in, run the full test suite:

```powershell
python test_rag.py
```

The suite runs 4 tests in order:

| Test | What is tested |
|---|---|
| **1 — DB** | Connection, schema exists, row count |
| **2 — Embedder** | Single embed (1536 dims) + batch embed |
| **3 — Ingest** | Parses any `.xlsx` in repo root → embeds → upserts |
| **4 — Validate** | Full pipeline with a sample narrative → GPT response |

Test 3 auto-detects any `P07`, `MPPR`, or `NDA` Excel file in the repo. If none is found, it is skipped.

## Deployment to Azure

### 1. Create the Function App

In the Azure Portal, create a new **Function App**:
- Runtime: Python 3.11
- OS: Linux
- Hosting: Consumption or Premium (Premium recommended for less cold start latency)
- Name: e.g. `nda-rag-function`

> Create this as a **separate** Function App from the original `azure_function/` deployment.

### 2. Set Application Settings

In the Function App → **Settings → Environment variables**, add all variables from the [Environment Variables](#environment-variables) section.

### 3. Deploy

From the repo root using the Azure Functions Core Tools:

```powershell
cd rag_function
func azure functionapp publish nda-rag-function
```

Or deploy via VS Code Azure Functions extension → **Deploy to Function App**.

### 4. Test Deployed Endpoints

Get your function key from the portal (Functions → ingest / validate → Function Keys), then:

```bash
# Test ingest
curl -X POST "https://nda-rag-function.azurewebsites.net/api/ingest?code=<key>" \
  -F "file=@P07.xlsx"

# Test validate
curl -X POST "https://nda-rag-function.azurewebsites.net/api/validate?code=<key>" \
  -H "Content-Type: application/json" \
  -d '{
    "narrative": "The SRO DCA remains Amber because...",
    "project_name": "Security Systems Architecture",
    "period": "P07"
  }'
```

## Troubleshooting

### `psycopg2.OperationalError: could not connect to server`
- Check `POSTGRES_HOST` — must include the full `.postgres.database.azure.com` suffix
- Verify the PostgreSQL server firewall allows connections from your IP (or Azure Services)
- Confirm `POSTGRES_SSL=require`

### `extension "vector" is not available`
- The pgvector extension must be allowlisted before running `setup_db.py`
- Go to Azure Portal → PostgreSQL server → Server Parameters → `azure.extensions` → add `VECTOR`

### `server_error` from Azure OpenAI
- Confirm the embedding and chat deployments exist in your Azure OpenAI resource
- Check `AZURE_OPENAI_API_VERSION` is compatible with your resource (try `2024-02-01`)
- Verify the API key has not been rotated

### Empty retrieval results (Test 4 gets `chunks_used: 0`)
- Run the ingest first (Test 3 or `POST /api/ingest`) to populate the database
- Check that `POSTGRES_DB` points to the same database where `setup_db.py` was run

### `KeyError: POSTGRES_HOST` (or similar)
- `rag_function/local.settings.json` is not filled in with real values
- Replace all `<YOUR_...>` placeholders with actual credentials
